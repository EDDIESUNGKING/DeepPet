DeepPet Version 9.04 — 性能與畫面一致性修正版
=========================================

基礎：DeepPet V9.03 完整 Netlify 工程，未重做應用，也未修改四級健康分數閾值。

1. 深入分析週期：單日、7 天、30 天。舊本地 state.range=3 或 14 時自動回退 7 天。
   14 天健康基準功能仍保留，因它是算法的個體參考期，非 UI 的分析時間切換選項。

2. 圓圈和數字：深入分析三大類的主分數圈與子指標分數圈均以 84×84 px、27px 數字為準。
   包括心肺四項、精力與恢復三項及睡眠主狀態；保留風險色。
   四級配色：>=90 綠色；80–89 藍色；60–79 橘色；<60 紅色。

3. HRV 文字：新增 RMSSD 和 SDNN 的白話定義及判讀限制，出現在單日／7 日／30 日的 HRV 卡片。

4. 心跳與呼吸：在每張指標卡僅留一個「查看波形」按鈕。
   按鈕打開完整獨立頁面：01 模擬即時 8 秒滾動波形；02 全天概要＋可切換最近七天日期＋標示值得回看的時段；
   03 放大特定時段前後約 30 分鐘的逐分鐘曲線，顯示日期、準確分鐘、當時讀數與當日均值。
   時段切換更新這三段，返回 Deep，不顯示主底部分頁。

5. 性能：每次 render 只產生同一隻寵物的示範日紀錄和節奏計算一次，減少 7/30 天切換時的重複運算。
   引導頁五張高畫質圖採用同尺寸 941×1672 的 WebP quality=100 以減少傳輸，原 PNG 保留。
   15 隻範例寵物新增獨立縮圖供小頭像使用，原照片保留供大圖顯示。
   JS/CSS 以版本 query 進行快取失效管理，Netlify 添加靜態資源快取規則。

測試資料與速度（相同桌面 Chromium 的模擬前端，不含實際網路／低階手機）
  V9.03 → V9.04 之精力與恢復視圖的中位渲染耗時：
  單日 61.55ms → 28.65ms；7 天 101.35ms → 28.35ms；30 天 293.05ms → 38.30ms。
  V9.04 頁面組合檢查 180 組，另額外驗證波形、所有分數等級配色及寬度，無 JS 錯誤。
  真實下載速度受網速和設備影響，無法保證所有手機絕對 0 延遲。

醫療限制：
  目前是前端可互動示範。動態波形是模擬圖，不是原始 255Hz BCG 或真實 20Hz SDK 監測；
  圈選時間是示範序列內的相對變化位置，不等於經證實的呼吸暫停或心律不整，不能預測猝死。
  正式上線前仍須接上真實設備 SDK、確認時間戳記與訊號品質，進行犬／貓不同品種情境驗證。

部署：可將此 ZIP 解壓後作為 Netlify 專案；build command: node build.mjs；publish directory: dist。
